# max_tg_gateway

Фоновый шлюз между Telegram и мессенджером MAX. Рассчитан на запуск как служба на Linux (Ubuntu).

## Возможности

1. **Мост Telegram → MAX.** Telegram-бот слушает сообщения; когда сообщение приходит от отправителя (или из чата), чей ID указан в таблице пересылки, его текст и/или фото пересылаются в заданный чат MAX. К пересланному добавляется подпись источника («ЛС | Иван», «Группа «Чат» | Пётр»).
2. **Ответы из MAX обратно в Telegram.** Для каждого пересланного сообщения запоминается соответствие «сообщение MAX → исходное сообщение Telegram». Ответ в приложении MAX (долгое нажатие → «Ответить») на пересланное сообщение уходит обратно в исходный чат Telegram как ответ на исходное сообщение.
3. **Чтение ссылок.** Сообщение со ссылкой от владельца (его MAX ID) обрабатывается: веб-страница возвращается читаемым текстом (длинная — файлом `.md`), прочий файл — пересылается вложением обратно в MAX.

## Конфигурация

Файл `ini.toml` необходимо создать рядом с `main.py`, используя `ini.toml.example` как шаблон:

```toml
[max]
token = "токен-бота-MAX"
owner_id = "ваш-MAX-ID"

[telegram]
on = "yes"
token = "токен-Telegram-бота-от-BotFather"

[tg_to_max]
"TG_ID_отправителя_или_чата" = "ID_чата_MAX"
```

- **MAX**: `token` — токен бота (нужен и для отправки, и для приёма входящих); `owner_id` — MAX ID владельца, от которого принимаются ссылки для чтения. Пустой `owner_id` отключает обработку ссылок.
- **Telegram**: `token` — токен бота от [@BotFather](https://t.me/BotFather).

### Таблица пересылки

Секция `[tg_to_max]` — соответствие «ID отправителя или чата в Telegram → ID чата MAX»:

```toml
[tg_to_max]
"111111111" = "-1001234567890"
"222222222" = "-1009876543210"
```

Строк может быть несколько. Для работы моста требуются `[telegram] on = "yes"` с токеном, непустой токен `[max] token` и хотя бы одна строка в `[tg_to_max]`.

Как узнать нужные ID:
- **TG_ID** — числовой id пользователя или чата Telegram (можно посмотреть, например, через @userinfobot, либо временно логировать `message.from.id` / `message.chat.id`).
- **ID чата MAX** — идентификатор чата в MAX.

### Файл состояния

Соответствия «сообщение MAX → сообщение Telegram» хранятся в `state.json` рядом с приложением. Файл создаётся автоматически и в репозиторий не коммитится.

## Запуск на Ubuntu

```bash
sudo apt-get update
sudo apt-get install -y python3-venv
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python main.py
```

## Запуск как служба systemd

Файл-образец — `deploy/max_tg_gateway.service`. Порядок установки:

```bash
sudo cp deploy/max_tg_gateway.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now max_tg_gateway
```

В файле службы необходимо привести к своей установке `User`, `WorkingDirectory` и путь к интерпретатору в `ExecStart`. Просмотр журнала:

```bash
journalctl -u max_tg_gateway -f
```

## Замечания

- Приём входящих MAX реализован через long polling (`GET /updates`). MAX рекомендует для продакшена webhook; его можно добавить позже, когда у сервера есть публичный адрес.
- Telegram-бот может писать в личный чат только тем, кто сам ему написал. Мост пересылает лишь те сообщения, которые бот уже получил, поэтому ответы уходят в доступные боту чаты.
